    05 — Built outside work

    The race that most streaming demos never notice.

    In AgentHub, every agent action funnels through a single emit() closure that writes three places: the audit row in Postgres, a Redis publish for live delivery, and a short-lived Redis list.

    That third write is the interesting one. Redis pub/sub only reaches clients that are already subscribed, and agents emit their first events within milliseconds — faster than a freshly navigated browser can open a socket.

    06 — How I decide

    Four decisions, and what each one cost.

    Each of these is a place where the obvious answer and the right answer differ. Every engineering decision costs something; these are the ones I chose to pay, and why.

    D1A quality gate the state machine can actually branch on
    Problem

    "Is this draft good enough?" is a judgement, and a model asked for a judgement returns prose. A state machine cannot branch on prose — and a revise loop with no exit condition is an infinite loop with a billing account.

    Decision

    The Critic returns a structured verdict: an approve/revise boolean and a 0–100 score, parsed into graph state. Routing reads the number. A revision cap of two bounds the loop, and the cap is enforced by the graph rather than trusted to the model.

    What it costs

    A genuinely weak third draft ships anyway, carrying its score. I would rather return an honest 68 than never return at all — and the score makes the weakness visible instead of hiding it.

    D2The event that arrives before anyone is listening
    Problem

    Redis pub/sub reaches only clients that are already subscribed. Agents emit within milliseconds of a task starting — well before a freshly navigated browser has a socket open. The first thoughts of every run were being dropped on the floor.

    Decision

    Every emit() writes three places: the audit row, the pub/sub channel, and a bounded Redis list. The WebSocket endpoint subscribes first, then drains the list, then de-duplicates by sequence number. Ordering the two steps that way makes duplicates possible and gaps impossible.

    What it costs

    A monotonic sequence per run and a buffer with a TTL — real state I now have to reason about and expire. I would rather own a bounded buffer than explain to a user why the first four thoughts of their task are missing.

    D3A stolen refresh token should cost the thief everything
    Problem

    A refresh token in localStorage means one XSS hole is a permanent session, not a temporary one. The usual tutorial puts it there anyway.

    Decision

    The refresh token lives in an HttpOnly cookie scoped to /auth and never reaches JavaScript; the access token is returned in the body and held in memory. Every refresh mints a new token and revokes the old one. Presenting an already-spent token revokes every session for that user — from the server's side a replay and a theft look identical, so the safe reading is theft.

    What it costs

    A user on a flaky connection can be signed out everywhere by a retried request. I will take that false positive; the alternative failure is silent and permanent.

    D4Authorisation that cannot go stale
    Problem

    A JWT that carries the grant is a permission frozen at login. Revoke someone's admin rights and nothing happens until their token happens to expire.

    Decision

    The token carries only which role the session is acting as, never the grant itself; the grant is read from the database on every request. require_admin is mounted on the router rather than on each endpoint, so a newly added admin route is locked by default instead of open by default. Model output is rendered as markdown with raw HTML disabled, so agent text can never become an injection vector.

    What it costs

    One extra read per request. It buys revocation that takes effect on the very next call, and a default failure mode of "locked out" rather than "wide open".
